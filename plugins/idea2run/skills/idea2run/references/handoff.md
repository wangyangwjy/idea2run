# 简短 Agent 提示词

每个阶段只完成一件有明确结果的事。目标是能复制、能理解、能检查；普通阶段尽量控制在约 300—600 个中文字，特殊步骤可以略长。辅助脚本限制每条最多 2400 个字符，超过时拆分阶段或精简内容。

## 格式

```text
目标：<用户目标>
方案：<选定项目、固定版本或待核对版本>
目录：<用户确认的绝对路径>
进度：<已完成阶段的简短摘要；失败时附本阶段阻碍>
本步：<阶段目标及必要操作>
验证：<可观察的检查项>
边界：<本步已批准的影响；保留已有文件，额外权限先说明>
返回：完成项、逐项验证结果、阻碍；不要自动开始下一阶段。
```

不重复方案搜索过程、所有候选、整份计划或大量日志。检查项使用短编号，方便反馈对应；结果只陈述真实执行情况。

跨 Agent 时带上本阶段依赖的前序产物路径、已确认条件和仍相关的未知项，不只说“接着做”。返回时附可检查的产物路径和必要的运行命令/结果摘要；文档判断、Agent 报告与接收方复核分开记录。接收方按成功标准检查实际产物后再推进，没收到反馈或未检查的内容保持待验证。

项目根目录、实际执行目录和输入/产物目录可能不同，分别写明；交接文件优先使用绝对路径，必须用相对路径时注明相对于哪个目录，避免“本目录”等歧义。路径缺失时反馈具体路径，不扩大搜索到未知目录。记录跨宿主结果时区分 Agent 应用与命令行环境；仅知道终端名称不能声称某个 Agent 宿主已验证。

写清哪些路径必须已经存在、哪些目录由本步准备。新建项目/输出目录已有授权时，在指定范围内创建并验证，不要求用户先手工建好；已有路径冲突则保留并反馈。输入或前序产物缺失仍停止，不能为了通过检查自行编造。

没有固定版本时，当前阶段只能核对并补齐版本，不能先安装任意最新版。示例步骤与命令必须按目标机器重新核对。需要根据前一步发现改变版本或操作时，修订计划并让用户审阅相关变化。

只做检查的阶段可以直接复制。具有额外影响的阶段，先展示影响并获得对应授权，再提供可执行提示词。预览稿要显著标为“只供审阅，未授权执行”。

## 返回结果后继续

用户把结果贴回 Idea2Run 后，对照本步检查编号读回必要产物，明确通过、失败与未运行项。能复核的实际复核；无法访问的产物仍是报告，不能编造本机执行证据。条件满足且授权未变化时直接生成下一阶段提示词，引用已通过阶段的必要产物路径和真实发现，不重复询问是否继续。

失败时保持当前阶段并给修复提示词；缺反馈时只补齐具体缺口。最后一阶段通过后按 delivery.md 的四项说明交付。保存本地进度时先记录本步结果，再生成下一提示词；示例或预览稿不能替代实际反馈。
