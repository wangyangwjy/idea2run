# 用户能直接使用的交付说明

在最后阶段验收后，或用户中途停止/只需要计划时使用。用用户语言，固定给出以下四项；不要只说“完成了”。

```text
做出了什么：<成果名称、实际完成/验证范围；可点击的文件、目录或已运行服务入口>
如何启动：<实际工作目录；最短启动命令或点击步骤；必要条件>
如何使用：<一个输入 → 操作 → 输出的具体例子；结果在哪里查看>
还有什么没完成：<剩余事项、未验证条件及最小下一步；没有则明确无已知未完成项>
```

- 路径用实际绝对路径，链接直接指向产物，不能只写“在项目里”。服务地址须来自实际启动结果，未启动时给启动方法并说明地址待确认。
- 安装启动与一次使用分开写。不要为了写启动说明擅自新增安装、下载、自动启动、全局配置或操作授权；已有授权内可完成的启动/使用检查应实际执行。
- 让用户知道怎样再次使用：入口、需要提供的输入、触发方式、输出位置。危险操作保留必要提示，不增加与当前成果无关的警告。
- 安装类交付先说明项目内/当前用户全局的范围，按用户选择给最短步骤，结果包含版本、实际入口和首次调用。下载目录与目标项目分别写清；更新先取得新版再操作，并说明备份和如何确认已升级，不要求用户猜入口或自己判断是否仍在旧目录。
- 面向普通用户，优先提供已具备的界面或启动入口。脚本启动后用简短文字说明状态、成果位置和下一步；提供简短用法或帮助入口，详细结构化日志按需查看。实际检查帮助能正常返回且不产生成果，启动输出中的路径确实存在；不为此增加无关界面或服务。
- 有输入样本时使用允许范围内的样本，不公开私人内容。没有真实样本就说明用法示例未经真实用户输入验证。
- 若只交付方案/计划/当前提示词，入口就是对应内容；启动写“交给 Agent 执行本阶段”或“从计划准备阶段开始”，未完成项明确应用尚未实现/运行。
- 交付过程发现问题，先修复当前阶段；不得把未运行或报告通过写成独立验收通过。
- 验收围绕用户确认的交付目标。测试插件时，示例程序或宿主 Agent 的额外兼容性、性能检查只用于找问题；未纳入本次目标的检查不成为插件交付阻碍。保留证据范围，不把插件可用扩大成所有宿主或所有产物均已验证。
