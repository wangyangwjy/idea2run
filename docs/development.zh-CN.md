# Idea2Run 开发与本地工具

[返回中文首页](../README.md) | [English](development.en.md)

本地安装脚本与辅助工具需要 Node.js 22+。以下命令在仓库根目录运行；纯对话使用不需要这些辅助工具。

## 本地开发安装

v0.3.0 增加 `--agent codex|claude-code|hermes|openclaw|pi`。以下旧命令不带 `--agent` 时仍是 Codex；其他宿主的安装路径、调用方式、工作区/项目条件、自定义目录环境变量及验证范围见[兼容说明](compatibility.zh-CN.md)。所有宿主共用源技能；安装后要使用对应宿主的调用方式。

克隆仓库后，在项目目录中安装技能副本：

```powershell
npm run setup
```

然后在 **项目目录中新开 Codex 对话**，输入 `$` 并选择 Idea2Run，直接说想法：

```text
$idea2run <你的想法>
```

需要在其他项目中使用时，明确目标目录：

```powershell
node scripts/install-skill.mjs "D:\你的项目"
```

默认项目内安装只在指定项目中复制 `.agents/skills/idea2run`，不改全局配置、不连接外部服务，并拒绝覆盖已有同名技能；明确加 `--update` 才替换已识别的 Idea2Run 副本。项目内技能发现及插件打包采用 [官方技能机制](https://developers.openai.com/plugins/build/skills) 与 [插件格式](https://developers.openai.com/plugins/build/plugins)。宿主版本和权限可能影响发现方式。

### 选择安装范围

- **项目内（默认）**：`npm run setup` 安装到本源码项目的 `.agents/skills/idea2run`，只在该项目及其子目录使用。指定其他项目时使用上面的目标目录命令；进入另一个项目不会自动拥有这份技能。
- **全局（当前用户）**：在源码/解压目录运行 `npm run setup -- --global`，安装到当前用户 `~/.agents/skills/idea2run`，可在该用户的各个项目使用。Windows 通常为 `%USERPROFILE%/.agents/skills/idea2run`，不需要管理员权限。

范围依据 [Codex 本地技能发现说明](https://developers.openai.com/codex/skills)。`--global` 不能与目标项目目录混用；只有明确选择它才写入用户目录。两种方式都不修改 Codex 配置或市场。项目内和全局是独立副本，同名技能不会合并；若两者同时出现，核对入口路径后选用，更新也要指定对应范围。

无需安装也可以直接让 Agent 阅读源技能文件：

```text
请读取 <仓库绝对路径>/plugins/idea2run/skills/idea2run/SKILL.md，并按它的流程帮我实现这个想法：<你的想法>。
```

开发时优先直接引用源文件，避免已复制的技能副本落后于修改。插件包位于 `plugins/idea2run/`，已包含便携清单与 Codex 兼容清单。仓库内提供插件列表，可通过上面的命令安装。

## 安装与更新

当前版本：**v0.3.0**。用户安装与更新从 [GitHub 最新发布页](https://github.com/wangyangwjy/idea2run/releases/latest)取得源码包，再选择安装范围。主分支包含后续开发时，以发布页的版本标签和附件为准；不要从旧源码目录重装并当作升级。

### 项目内技能

先取得新版源码或解压交付包，在该目录运行：

```powershell
npm run setup -- --update
# 安装在其他项目时明确目标：
node scripts/install-skill.mjs "D:\你的项目" --update
```

这也兼容以前未带安装标记的 v0.1.1 技能。更新时先准备新版，再把旧技能完整移动到目标项目 `.idea2run/skill-updates/update-*/previous`，然后替换技能入口。命令打印具体入口和备份路径，本地修改或额外文件仍在备份中，需要时迁移；现有 `.idea2run/` 进度不清空。尚未安装时 `--update` 完成首次安装。

遇到无关技能、符号链接/目录联接、已有安装锁或准备失败时停止，不移动旧技能；替换失败时尝试自动恢复旧副本。若恢复失败，明确打印保留的旧副本位置。备份不自动删除；需要回退时让 Agent 核对打印的备份与当前入口，另行执行明确授权的恢复，不直接删除整个 `.idea2run/`。

### 当前用户全局技能

首次安装与更新都在新版源码/解压目录运行：

```powershell
npm run setup -- --global
# 已有全局副本：
npm run setup -- --global --update
```

全局更新复用同一保留旧副本和恢复机制；备份位于用户目录 `.idea2run/skill-updates/update-*/previous`，具体路径由命令打印。不会更新项目内技能、清空项目进度或更改已安装的市场插件。本轮在隔离的用户目录实际验证全局安装/更新，未修改用户真实全局安装。

### 仓库市场插件

新版公开发布后，对于按 README 安装、市场名为 `idea2run` 的用户：

```powershell
codex plugin marketplace upgrade idea2run
codex plugin add idea2run@idea2run
```

市场名以实际安装来源为准，可用 `codex plugin list` 核对。`personal` 等本地市场不需要刷新 Git 快照；确认其源目录已更新后，用对应的 `codex plugin add idea2run@personal` 重新安装。不要默认刷新所有市场、修改 `marketplace.json` 或全局配置。更新命令已按本机 CLI 帮助核对；本轮未执行真实全局插件升级。

按所选范围更新后都要在可用范围内新开任务，输入 `$` 选择 Idea2Run。确认用的是新入口；如发现旧缓存或发现失败，可以让 Agent 直接读取当前源技能继续，不为此自动卸载其他安装。

安装输出须让普通用户看懂：当前版本、项目内/全局范围、真实技能入口、旧副本备份（更新时）和首次调用示例。用户安装到自己的工作项目时，从下载目录运行带目标项目绝对路径的命令，不把下载目录默认当作用户项目。

v0.2.3 增加显式全局安装选择及范围说明。插件验收检查需求澄清、方案、计划、交接/反馈、交付和安装/更新是否可用；示例应用的额外性能或宿主 Agent 的普遍兼容性不是本次插件交付门槛，未经测试仍保留未知。

## 用户看到什么

1. 说出想法；Idea2Run 先复述目标、输入输出、成功标准和硬条件，把影响选型的缺口合并成一次简短补问，通常 1—3 个问题。上下文已明确的不用再答，不影响路线的细节留到计划阶段。
2. 查看几个短方案：标明现成能用、需要改造或需要开发，写清能做什么、还差什么、适合原因、环境、必要下载、实施与维护负担，以及来源和未知项。
3. 选择方案；Idea2Run 展开该方案的完整执行计划。
4. 确认计划，决定自己实施或获取 Agent 提示词。
5. 一次复制一个阶段的提示词；把结果反馈给 Idea2Run，继续或修复当前阶段。
6. 最后固定收到“做出了什么、如何启动、如何使用、还有什么没完成”，包含直接入口、最短启动步骤和一个使用示例。

计划与提示词区分必须已有的输入/前序产物和本步将创建的新目录。已有创建授权时，准备阶段创建指定项目/输出目录并核对，不要求用户手工先建好；路径冲突保留，缺输入仍停止。v0.2.1 修复了实际体验中“新项目目录未创建便被检查阶段阻塞”的问题。

v0.2.2 补充启动体验检查：按用户能力提供已有入口，脚本显示简短状态、实际成果位置和下一步，并提供不触发实施操作的用法/帮助。详细结构化日志按需查看；核对首次启动、帮助和再次使用，不为此增加无关界面或服务。

联网搜索由宿主提供；没有搜索工具时会说明限制，请用户提供资料，或把候选保留为待核对。资料核对不等于安装或运行通过。

关键条件未答时先等回答，可以只读查资料，但不定推荐。用户暂时无法确定时，给按条件区分的初步路线并标“待确认”。只询问与当前目标有关的环境和负担，不要求填通用硬件表。

“现成能用”指完整项目经安装或配置即可满足关键需求；“需要改造”指完整项目还要改代码或接入能力；“需要开发”指需要用库、框架或示例构建缺失应用或核心功能。混合路线按主要缺口标记。标签描述文档支持的落地方式，不代表在用户环境已经跑通；关键适配条件未知时标“待确认”。优先完整项目，不为凑数推荐开发路线，与硬条件冲突的候选说明淘汰原因。

每个方案用短卡片或紧凑表格，共用条件合并说明，选型前不展开安装教程。来源注明实际核对日期、版本与许可或未知；下载体积、兼容性和耗时没有依据就保留未知，不能把没查到写成零下载或零负担。

## 轻量的本地交接工具

纯对话即可推荐方案。可选工具需要 Node.js 22+，只保存进度和生成文件，没有第三方依赖，不执行计划中的命令。

```powershell
npm run idea2run -- --help
```

Agent 需要保存进度时按技能的 `references/local-progress.md` 操作。保存内容包括想法、环境摘要、候选、所选方案、计划、确认和结果反馈；默认保存在被 Git 忽略的 `.idea2run/` 中。

工具区分选型、计划批准、Agent 交接选择和当前阶段授权。计划或方案改变会使旧确认与有效进度失效；失败不会跳到下一阶段。每条提示词最多 2400 个字符，超过时要求拆分或精简。机器信息未知时保持未知。

需求摘要复用 `idea` 和 `environment`；方案的落地方式与能力缺口写入 `summary`，环境、下载和实施工作写入 `requirements`，限制与未知写入 `caveats`，无需新增状态字段。跨 Agent 提示词包含本步依赖的前序产物路径与相关未知项；根据实际返回检查产物后再推进，文档判断、Agent 报告与接收方复核分别记录。

交接时分别写明项目根目录、实际执行目录和输入/产物目录。文件优先写绝对路径，相对路径注明基准目录；不使用含糊的“本目录”，路径缺失时反馈具体路径，不扩大搜索到未知目录。Agent 应用名称与命令行环境分别记录，终端名称不能证明某个 Agent 宿主已验证。

实际反馈满足本步检查、方案与授权未变化时，直接生成下一阶段提示词并引用需要的前序产物；不重复询问是否继续。失败保持当前阶段，缺反馈补具体缺口。最后一阶段通过后按 `references/delivery.md` 的四项说明交付；只生成计划或提示词时明确应用仍未实现/运行。

工具生成的下一提示词带最近通过阶段的反馈摘要，最多 240 字符，仍标为用户/Agent 报告；完整反馈保存在会话记录。摘要优先写关键产物路径，本步任务仍写全所需路径，不能依赖被精简的文字。

导出包含 `plan.md`、`session.json`，条件具备时另含 `current-prompt.md`。导出使用新目录，避免覆盖已有文件。此工具帮助记录确认，不能替代宿主的权限控制，也不能证明用户或 Agent 的报告真实。

## 开发与验证

```powershell
npm test
npm run check
npm run demo
```

`test` 检查状态推进、权限确认、版本未知、失败重试、反馈完整性、变更后失效，以及中文/空格路径、防覆盖、旧版更新备份、进度保留、无关技能与目录链接保护、准备失败和安装锁。

`check` 检查插件清单、版本一致性、引用、文件编码和脚本语法。

`demo` 使用**合成测试数据**在 `.idea2run/` 中生成计划与两个阶段的提示词。没有下载、安装或运行任何开源候选，不是真实任务落地证据。测试数据留在 `tests/`，不会打入插件包。

另有一次实际的宿主内分步交接记录：一个 Agent 根据源技能澄清 README 链接检查需求并核对准备，另一个没有前面对话的新 Agent 根据当前提示词与准备产物开发本地工具，接收方再独立运行验收。真实两份 README 的 14 个本地链接通过，输入未被修改；报错行为使用另行标注的合成探针验证。随后收到一次用户手工转交后的 Agent 执行报告：真实输入与三个报错探针均符合预期，接收方本地复核一致；报告暴露的路径歧义已修正。对方具体 Agent 宿主未明确，修订提示词尚未由对方重验。记录和工具保存在被忽略的 `.idea2run/`，不打包进插件；这些结果不证明所有 Markdown 写法、跨宿主兼容性或从选型到交付的全部交互均已通过。

v0.2.0 另实际完成三阶段本地交接：新 Agent 收当前提示词后安装并返回；接收方读回产物后生成下一阶段，新 Agent 更新并返回完整旧副本路径；复核发现验证期间补充的反馈摘要未进入副本，先留在更新阶段修复，再交给新 Agent 验收并按四项格式交付。最终全部 7 个技能文件一致，实际旧副本完整保留，安装副本的工具帮助入口退出 0。本轮测试备注为明示样例，实际安装、更新、文件核对及帮助运行是真实执行；不据此声称不同宿主或新任务自动技能发现已经通过。

```text
plugins/idea2run/                可分发插件
  skills/idea2run/SKILL.md       对话工作流
  skills/idea2run/references/    按需读取的交接格式与进度说明
  skills/idea2run/scripts/       本地进度和导出工具
scripts/                   安装、检查与合成演示
tests/                     流程测试与合成输入
```

## 版本发布与 GitHub 同步

每个发布版本都提供 GitHub 源码、`v版本号` 标签、Release 和 `idea2run-版本号.zip` 下载包。用户从[最新发布页](https://github.com/wangyangwjy/idea2run/releases/latest)安装；不能把仅本地完成当作线上已更新。

1. 更新 `package.json`、lock、两个插件清单、双语首页/开发/兼容说明和双语 CHANGELOG。`npm run check` 要求当前版本一致，标签发布时还校验标签与清单。
2. 运行 `npm test`、`npm run check`、`npm audit --omit=dev`；核对实际安装/更新、文档和 `git diff`，提交只包含公开文件。
3. 在用户已授权 GitHub 同步的范围内提交并推送到 main，为同一提交创建并推送对应版本标签。未得到发布授权时只准备可审阅改动；已有明确授权不重复询问。
4. `.github/workflows/release.yml` 在 main/PR 上检查；版本标签在 Linux 和 Windows 的 Node.js 22 检查均通过后，自动生成完整源码 ZIP、SHA256SUMS 和双语更新说明，发布 GitHub Release。失败先修复，不覆盖已发布标签或伪造成功。
5. 实际核对远端提交、标签、Release 版本和下载附件，确认包中清单版本一致、没有私人记录，最后向用户给发布链接和最短用法。源码推送成功但 Release 未完成时仍说明发布未完成。

v0.2.4 将首次使用写成“选范围 → 安装 → 说想法”，安装输出新增版本和调用示例；此后的版本按以上流程同步 GitHub。工作流只使用 GitHub 内置令牌，没有新增账号或凭据配置。完整源码包包含公开文档、脚本和测试；安装出的技能副本仍只包含插件技能内容。

## 贡献

优先提交实际流程中的问题：用户目标、选定路线、失败阶段、可公开的最小复现。删去私人路径、输入内容和令牌。

保持主流程短，新增能力必须帮助用户更快得到可用结果。修改工作流或辅助脚本后运行测试和检查。真实来源、文档核对和运行反馈分别说明，不将合成数据写成实测记录。
